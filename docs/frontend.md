# 前端规范

适用：`src/pages/`、`src/client/`、`public/assets/*.css`。本规范提炼自当前产品源码，并明确新功能应补齐的质量要求；不表示旧页面均已符合。协作入口：[参与开发](../CONTRIBUTING.md)。

## 技术组织

- 继续使用原生 HTML、CSS 和浏览器 JavaScript。不要为单个表单引入整套 UI 框架、CSS 框架或构建链。
- 页面骨架放 `src/pages/*.html`；交互放 `src/client/*.txt`，由 `src/index.ts` 映射到 `/assets/*.js`。新增脚本必须同步路由和检查脚本。
- 共享主题、字体和基础控件在 `app.css`；后台布局在 `desk.css`；申请/审计等后台管理组件在 `admin.css`。保持后台加载顺序 `app → desk → admin`，避免无意扩大样式作用域。
- 新账号页可增加专用样式/脚本。重复的 API、存储、弹层行为先小范围抽取，不复制第四份实现，也不借机重写整站。
- `design/` 仅用于参考。检查最终由 Worker 返回的页面，不能用设计稿截图替代验收。

## 视觉基线

温暖纸色、墨色文字、棕色强调、细分隔线、克制的圆角和阴影；保留“糖包/笼屉”的人工手作语气。管理及账号表单采用清楚的普通中文，装饰文案不能遮蔽错误、权限和下一步。

| 用途 | token / 当前值 | 使用规则 |
| --- | --- | --- |
| 页面/侧栏/面板 | `--bg #fcfbf9` / `--side #f4f2ee` / `--panel #fff` | 复用变量，不在组件里写一套白底 |
| 正文/次级/辅助 | `--ink` / `--ink-2` / `--muted` | `--faint` 不用于关键说明或错误 |
| 分隔/交互 | `--line`、`--line-2`、`--hover`、`--hover-2` | 交互状态使用已有变量 |
| 强调 | `--accent #a8622a` / `--on-accent` | 主按钮和重点信息，避免所有元素都高亮 |
| 状态 | `--up`、`--dot`；后台 `--danger` | 状态同时显示文字，不能只靠颜色 |
| 字体 | `--sans`、`--serif`、`--mono` | 正文/控件用 sans；标题可用 serif；ID/代码/口令用 mono |
| 内容宽度 | `--col: 46rem` | 对话阅读保持现有节奏，表单使用受限宽度 |

正文基线 `15px/1.55`。已有控件常用约 9–12px 圆角，按同页相邻控件选用。品牌图标复用 SVG `symbol/use`，不额外引入图标字体。新字符要保证系统字体回退；不要假定 serif 子集覆盖所有账号文案。

主题由 `body[data-presence="awake|asleep"]` 和 CSS 变量控制。新组件应在昼夜主题都可读，不自行将操作系统深色偏好覆盖为另一套规则。后台与前台的在线语义由接口决定，样式不能决定业务状态。

## 布局和响应式

- 沿用 flex/grid 和现有断点：对话约 `768px`、局部控件 `640/520px`；后台 `1180/860/640px`。修改前检查同一元素的多处 media rule，避免靠追加规则制造冲突。
- 至少检查 390px 手机和 1440px 桌面，同时查看 768/860px 附近切换。长邮箱、长型号、中文错误、图片/代码块不能撑出横向滚动。
- 使用 `min-width: 0`、受限滚动容器和合理折行；移动端表单考虑软键盘、输入框和主要操作的可见性。
- 触控操作保留足够点击区域（建议至少 44px）；不要仅靠 hover 展示必要操作。
- 不新增固定高度截断错误和验证码内容。布局变动不能让正在输入的草稿或当前对话滚动位置丢失。

## DOM 和数据边界

- 语义优先：导航用链接，执行动作用 `button`，表单用 `form`，每个输入有可访问名称和显式 label；非提交按钮声明 `type="button"`。
- 用户消息、型号、邮箱和错误使用 `textContent`。`innerHTML` 仅用于固定模板或经过明确转义/安全渲染的内容，不拼接不可信字符串。
- Markdown 入口复用 `md.txt`；链接仅允许已支持的协议，新窗口使用 `noopener noreferrer`。KaTeX 保持 `trust: false`。渲染变更需验证代码、链接、表格和恶意输入。
- localStorage 读取需校验结构，读写均处理禁用/配额错误。新登录 session 使用 HttpOnly cookie，不把密码、验证码、邮箱重置凭证或管理员凭据放入 localStorage。
- `x-visitor`、URL 参数、按钮状态都是不可信输入。服务端返回的权限和所有权是最终依据。

## 异步与交互

- 每个请求流程明确初始、加载、空、成功、失败、禁用状态；错误提供下一步。网络失败时保留已输入文本、附件和用户上下文。
- 异步返回用请求序号/实体 ID 校验或 AbortController 防止旧请求覆盖新选择；切换对话、搜索和后台队列均需考虑竞态。
- 提交期间禁用相应按钮并防重复；前端 guard 只是体验，创建对话、申请、认领等仍需服务端幂等或条件写。
- 不自动重试可能重复写入的请求；幂等键和服务端结果明确后才重试。超时与“服务器已写入但回包失败”要能区分或查询。
- 轮询保持单一可取消计时器，失败退避，不因手动刷新或 visibilitychange 产生并发链。不要仅为了更新视觉每秒请求后端。
- 新对话/切换对话/注册拦截不得将请求结果写入另一个对话。第二次匿名创建被拦截时，应先保存草稿和附件的可恢复状态。

## 键盘和可访问性

- 保留 `:focus-visible`。输入框移除默认 outline 时必须有同等可辨识的替代焦点样式。
- 聊天 Enter 发送、Shift+Enter 换行；后台 Ctrl/Cmd+Enter 提交；始终检查 `event.isComposing`，不打断中文输入法。
- 弹层设置 dialog 语义、标题和 `aria-modal`；打开时移动焦点，Tab 限定在弹层，背景 inert，关闭后恢复触发点。Escape 只关闭最上层。
- 状态更新使用适度的 `role="status"` / `aria-live="polite"`，错误用 `role="alert"`；不要整页反复播报历史消息。
- 展开控件同步 `aria-expanded`、禁用同步原生 disabled 或语义。兼顾 `prefers-reduced-motion`。
- 昼夜两套主题均检查普通文字和错误对比度；目标为正文至少 4.5:1、大字及必要非文本元素至少 3:1。

## 账号界面专项

- 登录使用 `autocomplete="username"` 和 `current-password`；注册/重置使用 `new-password`，验证输入使用 `one-time-code`，允许粘贴和密码管理器。
- “验证邮箱”和“登录”是不同动作；普通登录不发验证码。展示重发冷却、验证码失效和找回说明，不披露邮箱是否已注册。
- 申请 AI 先检查登录及邮箱验证，普通用户注册成功不等于申请通过或获得后台权限。
- 匿名首段可继续；第二段提示注册且保留草稿。解释清楚注册用途，不使用“消息已发出”掩盖被拒绝的创建。
- 旧模型绑定显示将认领的型号、已验证邮箱、冲突/已绑定状态；不展示其他人的邮箱、旧口令或会话凭据。

## 完成标准

Issue 中附合成数据的操作步骤/截图；记录桌面及手机、两主题、键盘、失败恢复和影响到的共享页面。执行类型与脚本检查并如实记录覆盖范围。纯文档改动不要求新增镜像实现的测试；业务行为变更补对应有效回归。
